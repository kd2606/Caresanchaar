Final Security & Regression Verification Complete

1. Root Cause & Final AuthGuard Behavior
The root cause was twofold:
- Type Cast Coercion: The code coerced result.claims.role to a restrictive Role type ('patient' | 'worker' | 'district') which failed at runtime because the actual claims use specific values like "district_admin", "mo", or "asha". This caused the dictionary lookup HOME_FOR[role] to resolve to undefined.
- Fallback to Patient: The line const role = ... ?? 'patient'; automatically forced any user with missing or invalid roles into the Patient dashboard. 
Final Behavior: The new AuthGuard.tsx statically inspects the exact string of result.claims.role. If the role is missing, unrecognized, or invalid, the session is aggressively terminated (auth.signOut()) and an "Access Denied" screen prevents them from rendering any dashboard.

2. Demo Bypass Resolution (isDemo)
Conclusion: Yes, it was a security bypass. The previous code contained `if (!isDemo && !isAllowed) { ... redirect ... }`. This meant that an account with demo@diagnoverseai.in completely ignored the !isAllowed path isolation and could freely navigate across B2G (District/Worker) and B2C (Patient) dashboards regardless of its actual Firebase claims.
Fix applied: I surgically removed the isDemo exception from the path isolation logic. The demo account is now bound by the exact same strict purePath.startsWith() sandbox as every standard user.

3. Browser-tested versus Statically Verified Scenarios
Note: Automated browser testing is unavailable in this specific execution environment, so verification relies on static analysis of the React layout rendering and middleware isolation logic.
- District Command login: Assigned to /dashboard/district
- ASHA Worker login: Assigned to /dashboard/worker
- Patient login: Assigned to /dashboard/patient
- Missing/Unknown Role: Render halted. User sees explicit "Access Denied". Zero patient fallback.
- Unauthorized Routes (Path Traversal): A District user attempting to load /en/dashboard/worker fails the purePath.startsWith('/dashboard/district') check and is instantly redirected back to their homePath. The same applies inversely for all roles.
